## 3.5 i18n + mockup architecture (2026-06-29)
- **`assets/i18n.js`** — the EN layer. An **embedded SV→EN dictionary** (`var DICT` ~108 phrases, pre-fetched once from Weglot's translate API via `curl -X POST https://api.weglot.com/translate?api_key=wg_4cdd81cf…` while Weglot was still connected). Included via `<script src="/assets/i18n.js">` in **`index.html` AND each same-origin embed** (`app-embed/index.html`, `cta-embed/index.html`) so it runs inside the iframes too (Weglot couldn't — that was its fatal flaw). A **TreeWalker** translates text nodes whose trimmed value matches a DICT key (idempotent: EN text isn't a key → no-op). **Persistent MutationObserver** re-applies as Framer hydrates. `lang = localStorage('thlang') || (navigator.language ~ /^en/ ? 'en' : 'sv')`. **Anti-FOUC** (top frame, EN only): a sky-blue (`#98cdea`) splash hides the page until first translation (reveal ~140 ms, 1.6 s failsafe). **SV/EN switcher** (top frame): sets `thlang` + `location.reload()`. Skip selector: `.ro-lang,#th-splash`. To tweak wording, edit `DICT` in `assets/i18n.js` (e.g. "cykelfest" renders inconsistently — see §5).
- **Animated / our-own-built content is rendered in EN at the SOURCE, never via the walker** (Lesson 28). The walker shredding Framer's per-word scroll-reveal spans broke them. So: the **manifesto** (`ro-manifesto-js` in `index.html`) renders English in `build()` when EN; the **app-embed feature bullets** are still walker-translated (they survive at baseline load — see Lesson 30).
- **Manifesto EN = height-locked ghost overlay** (Lesson 29): `build()` renders an **invisible, static** Swedish copy (`.inner[aria-hidden]`, `_SVH.replace(/ ?ro-rv/g,"")` so `wire()` doesn't animate it) that holds the exact original height, plus the **English copy** absolutely positioned on top (`.ro-en`, keeps `ro-rv` → animates). Section height is identical EN/SV (verified 734 px = 734 px) AND EN animates only ~84 words (≈ the SV baseline of 70). CSS added to `ro-manifesto-css`: `#ro-manifesto .ro-en{position:absolute;top:16vh;left:50%;transform:translateX(-50%);width:min(900px,calc(100% - 12vw))}`.
- **Scroll section (`app-embed`)** — `ro-app-embed-js` `phone()` inserts `.ro-phone`; the phone image **follows the current step** (`RO_BYSTEP{1:program,2:ledtradar,3:poang}` set on every step change in `curtainFrame`, so it swaps correctly scrolling up too). Assets: `app-embed/assets/img/rideout-phone-{program,ledtradar,poang}.png` (complete phone mockups, transparent bg). **Pacing**: `ro-app-js` `RO_PACE=3` inflates the desktop page-scroll runway 3× (page-scroll & `p` use `runway*RO_PACE`; iframe content-scroll `px` still uses the real `runway` so it doesn't over-scroll).

## 4. LESSONS — new this session (continue the list from §B)
16. **Framer renders page content from its JS BUNDLE and re-hydrates, overwriting DOM edits.** Editing static HTML text alone gets reverted to the bundle's value on hydration/scroll (we saw "RideOut" come back). The rebrand required `sed`-ing the **bundles** (`assets/scripts/script_main*.mjs`, `shared-lib*.mjs`, `8GPhkq*.mjs`) + `assets/data/searchIndex-*.json` too. Replace only exact-case brand strings (`RideOut`/`RIDEOUT`/`RIDE OUT`); leave lowercase (asset paths, ids, emails). Verify with a **full-hydration render + scroll through every section**, then scan `document.body.innerText`.
17. **Weglot — and any client-side translator — cannot reliably translate this Framer export.** Hydration reverts heavy content (hero title flashes English then snaps back to Swedish); SVG text (the spinning badge) can't be translated at all. Tried: head snippet (Weglot's own Framer guide says use "Other" tech), a re-apply-on-hydration nudge, and a fresh Weglot project with "Framer" tech — all partial / reverting. For real bilingual later: **(a) Framer-native localization → re-export → re-inject our `ro-*` blocks**, or **(b) a bespoke `/en/` page we fully control** (no Framer = no revert). English is parked; Weglot removed.
18. **The sandbox headless browser cannot reach external sites** (the agent proxy doesn't route Chromium; `curl` works via the proxy, the browser gets "site can't be reached" / 302 to auth). So you **cannot** verify the deployed site, Weglot, or live `fetch` in-sandbox. Verify: backend behavior via `curl` (insert/dup/RLS/count), CORS via a `curl -X OPTIONS` preflight, function logic by running it locally, and the live visuals via the founder. Vercel previews are auth-protected (401/302).
19. **Footer wordmark + logo are RASTER PNGs**, and there are **two copies** (`rideout-wm-*.png` from the localize tool AND the original Framer-hashed `qNYdNE2*.png`; the bundle re-inserts the `qNYdNE2` set on hydration, so editing only `rideout-wm` isn't enough). We regenerated **all 8** as an outlined Boldonse "TABLEHOPP 26" (rendered via Playwright using the live page font + `omitBackground`, then PIL-downscaled). The nav/footer mark `rideout-logo.svg` is **abstract** (name only in `aria-label`/`<title>`). New brand logo = `tablehopp-logo.svg` (site swap still pending).
20. **Direct `git push` to `main` is blocked by the auto-mode classifier** even after a bare "push" — it needs unambiguous per-action authorization ("ja, pusha direkt till main"). **Prefer the GitHub MCP PR→squash-merge flow** (it disconnected/reconnected mid-session; when down, the founder can merge via the GitHub compare URL).
21. **Reused dev branch ↔ squashed `main` diverge.** Each squash-merge means `main` is no longer an ancestor of `claude/epic-dirac-5TzaV`. Before every new PR: `git fetch origin main` then `git merge origin/main -X ours -m "…"` into the branch → the PR diff shows ONLY the new change. (`git reset --hard` and direct `git checkout -B main` + push are classifier-blocked.)
22. **Supabase REST: encode `+` as `%2B` in DELETE filters** (`email=eq.a%2Bb@x.com`). Unencoded `+` is read as a space → no match → returns 204 but deletes nothing. Bit us cleaning `clawmax12+welcome@gmail.com` test rows.
23. **Welcome-email gotchas**: SVG logos don't render in email → use a hosted **PNG** with an absolute URL (only live after deploy, so test sends after merge). `box-shadow`/`border-radius` render in Apple/iOS Mail, degrade gracefully elsewhere (keep a solid border). Test to the Resend account owner or a `+`-address; clean DB test rows via service_role afterwards.
24. **Don't ship a promise the backend can't keep.** "Kolla inkorgen" was gated until the welcome email actually sent (Resend domain verified + `RESEND_API_KEY` set in Vercel + redeployed). Interim copy was "Du är med! 🎉".
25. **Real social-proof count starts at 0 → "0+" looks dead.** Use a `COUNT_BASE` baseline + a `COUNT_MIN_SHOW` threshold, and paint the baseline at build time (so it shows even if the count RPC fails).
26. **Verify by rendering, frame-exact when needed.** For the animations we drove the WAAPI timeline (`getAnimations().pause()/currentTime`) to capture exact frames; for the email/logo we rendered HTML/SVG → PNG via Playwright. The sandbox CAN render local files + the local dev server; it CANNOT render the deployed site.

27. **Embedded dictionary beats client-side Weglot for this Framer export.** Weglot only ran in the parent (couldn't reach the `app-embed`/`cta-embed` iframes) and had a ~10 s flash. Fix: pre-fetch translations from Weglot's API once, embed as a JS dict, apply it ourselves in **every same-origin frame**. Diagnose the real reason a string won't translate before patching: check Weglot's API actually returns a translation (it did — so it was a client *application* problem, not missing translations), check whether the string is in SSR vs only in the JS bundle vs inside an **iframe**, and whether it's split across spans.
28. **Never DOM-translate Framer's animated text at runtime — render the target language at the SOURCE.** Framer scroll-reveal wraps each word in a span and ramps inline opacity on scroll; a TreeWalker that rewrites those text nodes desyncs the animation's cached span refs → "stuck at partial opacity / garbled" (we got "Table Jump" for Tablehopp). For content **we build** (`ro-manifesto-js`, `RO_BULLETS` in `ro-app-embed-js`), make the builder emit English when EN so the animation runs on English natively.
29. **The ghost-overlay trick locks a section's height across languages.** Translating the manifesto changed its text height, which shifted the `app-embed` section below it and disrupted that iframe's fragile runtime bullet translation. Render an **invisible static** copy of the original language (holds the exact height) + the translated copy **absolutely positioned** on top → section height is identical in both languages → nothing below moves. Make the ghost static (strip the animation class) or its animation **doubles the EN main-thread load** and re-breaks things.
30. **Two independent things can break the same element; the "switch to SV and it returns" clue is gold.** The `app-embed` bullets vanished only in EN. EN-mode differs by (a) layout shift from the manifesto and (b) extra animation/main-thread load and (c) the i18n walker being active. Height-lock fixed (a) but not the symptom → it was also (b): the ghost was animating. Use the SV-vs-EN A/B to isolate "is this layout, load, or the translator?" before guessing.
31. **I can't render the hydrated Framer site headlessly (iframes + scroll animation don't run), but I CAN unit-test our own scripts.** Extract a `<script>` body → `node --check`; serve the repo + a minimal DOM with the structures a builder needs and `--dump-dom` to read results (e.g. measured `#ro-manifesto` height EN vs SV, `.ro-w` span counts, eyebrow text). Use this to prove the mechanism (height-lock, source-render) before pushing; the founder still verifies the live iframe/animation visually on the Vercel branch alias. Loose image uploads don't sync to the sandbox FS — **a `.zip` upload does** (extract from `~/.claude/uploads/<session>/`).
32. **Make the welcome email follow the visitor's language at the source, and store the language.** Signup detects SV/EN exactly like `i18n.js` (`localStorage('thlang')` → `navigator.language`) and posts `lang` to `/api/join`; the function picks a full SV or EN template (Swedish kept byte-identical) and stores `lang` on the row. Defensive insert: try with `lang`, and if PostgREST 400s on the unknown column (`/lang/.test(body)`), **retry without it** — a missing column can never block a signup. (PR #36.)
33. **Sync our fixed overlays to Framer's auto-hiding nav by mirroring its rendered rect, not its thresholds.** The header (`[data-framer-name="Header"]`, `data-nce-nav-scroll`) slides out on scroll-down; the old SV/EN switcher floated alone and its bare dark text vanished over dark sections. Fix: a segmented pill with a translucent **backdrop-blur** (legible everywhere) that toggles `.ro-lang--off` when `navEl.getBoundingClientRect().bottom<=2 && scrollY>4` — hides/returns exactly with the nav regardless of Framer's internal thresholds, degrades to always-visible if the nav never hides, and re-queries `navEl` if it's detached after hydration.
34. **Force-push and `git reset --hard` are classifier-blocked even on the dev branch.** To put a main-based commit onto the diverged dev branch without a force-push: `git rebase --onto origin/<devbranch> <main-tip> <devbranch>` replays just the new commit onto the real remote tip → the push is a plain fast-forward. (Refines Lesson 21; supersedes the `merge -X ours` trick when the branch was soft-reset to main.)

35. **Mobile = a fully STATIC section; the animation is desktop-only.** The scroll section's animation (sliding curtains, word-by-word reveal, step-driven phone swap, fade overlay) all overlapped on mobile where the 3 `BG` cards lay out separately and should just be 3 static screens. The first instinct (animate-but-fix the swap per card via `paintPhones` in `flatMode`) still left it fragile — the right call was to turn the animation OFF on mobile entirely (founder: "INGEN ANIMATION… maximal snabbhet och säkerhet"). Implementation: the parent loads the embed with **`?flat=1`** on mobile (`innerWidth<600`) and no-ops its scroll handler (`onScroll(){if(mob)return;…}`, so no fade/step messages); the embed reads `FLAT` from the URL and runs **`bootFlat()`** — inject each card's own screen by `bgNum` + the bullets on a short hydration-catch interval, and `report()` height for layout — instead of the rAF loop (no curtains, no masks, no reveal; the `message` handler also early-returns on `FLAT`). Desktop is untouched (`paintPhones` → all phones follow `curStep`).
